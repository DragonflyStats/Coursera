## Task 1 - Getting and Cleaning the Data

Large text databases in a target language commonly train language models for various applications. In this exercise, focus primarily on the English database, though three additional databases exist in German, Russian, and Finnish.

The goal of this task is to explore the databases and execute necessary cleaning steps. By the end of this exercise, you should understand real-world data characteristics and the effort needed to clean it properly. When developing for a new language, the priority is understanding language-specific traits relative to your target. You can learn to read, speak, and write the language, or analyze existing linguistic patterns via literature and web resources. At minimum, understand how the language is written: script, input methods, phonetic structures, etc.

*Note: The data contains offensive and profane words. These remain intentionally to highlight real-world developer content moderation needs.*

### Tasks to Accomplish

* **Tokenization:** Identify appropriate tokens (words, punctuation, numbers) and write an R function that accepts a file as input and returns its tokenized representation.
* **Profanity filtering:** Remove profanity and other non-predictive terms.

### Tips, Tricks, and Hints

* **Loading the data:** The dataset is fairly large. You do not need to load the entire dataset to build algorithms. Initially, work with a smaller subset. Reading chunks or lines using R's `readLines()` or `scan()` functions is effective. Loop over lines using `readLines()` within a `for` or `while` loop, though reading larger chunks at once performs faster. Processing pieces at a time requires an R file connection:

```R
con <- file("en_US.twitter.txt", "r") 
readLines(con, 1) # Read the first line of text 
readLines(con, 1) # Read the next line of text 
readLines(con, 5) # Read in the next 5 lines of text 
close(con)        # Always close the connection when finished

```

* **Sampling:** Building models does not require loading all data. A small, randomly selected set of rows or chunks often yields an accurate approximation of full-dataset results. Use representative sampling concepts from statistical inference to draw conclusions about the broader population. Consider writing a random sample to a standalone file to avoid recreating it repeatedly. The `rbinom()` function can simulate a "biased coin flip" to determine line inclusion.

## Task 3 - Modeling

The objective of this task is to build an initial model capturing relationships between words. This forms the basis of a predictive text application. You will explore basic models before moving to advanced techniques.

### Tasks to Accomplish

* **Build a basic n-gram model:** Utilize exploratory analysis findings to build an n-gram model that predicts the next word based on the preceding 1, 2, or 3 words.
* **Handle unseen n-grams:** Account for cases where user inputs contain word combinations absent from the training corpora.

### Questions to Consider

* How can you efficiently store an n-gram model (e.g., Markov Chains)?
* How can word frequency knowledge optimize model size and execution speed?
* How many parameters are required (i.e., what is the optimal $n$ in your n-gram model)?
* How can probability estimation be smoothed (e.g., assigning non-zero probabilities to unobserved n-grams)?
* How do you evaluate model accuracy and effectiveness?
* How do backoff models estimate unobserved n-gram probabilities?

### Tips, Tricks, and Hints

Two key performance factors require ongoing balance throughout model development:

* **Size:** The physical RAM required to run the model in R.
* **Runtime:** The time taken to return a prediction given an input.

Predictive text algorithms frequently operate on mobile devices with restricted memory and CPU capacity. Carefully manage object memory consumption and inference execution time. Ultimately, the model must run efficiently within a Shiny application hosted on [shinyapps.io](https://www.shinyapps.io/).

Useful optimization tools in R include:

* `object.size()`: Reports memory occupied by an R object in bytes.
* `Rprof()`: Runs the native R profiler to identify code bottlenecks. The `profr` package on CRAN helps visualize profiling metrics.
* `gc()`: Triggers garbage collection to reclaim unallocated RAM and displays current overall memory usage.
